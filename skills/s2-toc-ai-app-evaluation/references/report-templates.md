## 3. L3 模板

### Highlights

- 一句话结论
- 为什么是现在
- 机会背后的哲学
- 需要在哪几层做功
- 哪些层难做且可能构成壁垒

### 产品是什么

- 一句话定位
- 核心用户与 Job to be Done
- 概念/实体关系图

### Step by Step

按注册、激活、核心任务、结果、复用/留存路径排列截图。每张截图配一句“这一步为何重要”。

### 高光 Case

- 来源与时间戳
- 发生了什么
- 体现什么能力
- 与普通任务的差别
- 可复现步骤与证据

### 创始人思想

- 原始论点
- 必要的中英对照短引
- 来源、时间与上下文
- 对产品设计/战略的具体映射
- 分析者判断

### 深度履历

用时间轴展示能力如何形成，突出具体项目、开源贡献、关键选择和联合创始人关系。

### 战略判断

- 核心论点成立条件
- 已被证明的部分
- 尚未被证明的部分
- 壁垒证据与反证
- 做成后的价值
- 失败路径

## 5. 发布结构

Hi 文档默认结构：

- 父文档：S2 ToC AI 应用测评框架总览与索引
  - 产品 A — L1 基线测评
  - 产品 A — L2 舆情分析（若执行）
  - 产品 A — L3 One-pager（若执行）
  - 产品 B …

单篇预计超过 5,000 字时拆分，父文档保留一句话结论、深度标签、日期和子文档链接。

若无法直接发布 Hi 文档，交付 Markdown/文档文件并保持相同标题层级，同时说明需要用户粘贴或提供连接权限。

## 6. 交付检查清单

### 范围

- [ ] 已写明对象、版本、时间、地区、价格档和深度。
- [ ] L2/L3 的选择理由明确，没有机械升级。
- [ ] 覆盖盲区和权限限制已披露。

### 测试

- [ ] Use Case 来自真实场景，不是拍脑袋 demo。
- [ ] 3–6 个任务覆盖不同能力维度。
- [ ] 完整 Prompt、输入、输出、耗时、成本可追溯。
- [ ] 成功和失败都被记录。

### 用户声音

- [ ] Buy-in 与不 Buy-in 人群分开分析。
- [ ] 官网证言与独立口碑分开。
- [ ] 引用包含渠道、作者、时间和链接。
- [ ] 同名噪声已排除。
- [ ] 未找到/不可访问的平台已列出。

### 证据

- [ ] 融资、用户规模、核心履历、核心技术声明已跨类型双源验证。
- [ ] 单源事实标明来源性质。
- [ ] 推论使用【推论】且内部一致。
- [ ] 信源冲突已显式呈现，不能调和的标为【信息缺口】。

### 判断

- [ ] 开头有明确结论。
- [ ] 已解释谁会买单、谁不会以及为什么。
- [ ] 已区分频率与严重度。
- [ ] 已给出风险、待验证项和“什么证据会改变结论”。
- [ ] L3 的“为什么重要”来自真实一手材料。
- [ ] 团队自述壁垒已用第三方证据或用户反馈核验。

### 发布

- [ ] 文档结构适合目标读者。
- [ ] 超过 5,000 字时已考虑拆分。
- [ ] 父索引与子文档关系清楚。
